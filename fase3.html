Simulación de Ataque en Tiempo Real - Controlado

IP objetivo: 217.154.224.228

Paso 1: Verificación de Servicio Web

Comando: curl -I http://217.154.224.228/

  • Servidor Apache activo, responde con HTTP 200 OK.
  • Faltan cabeceras de seguridad: X-Frame-Options, X-Content-Type-Options.
  • Posible filtración de metadatos vía ETag.
  • Métodos HTTP permitidos: GET, POST, HEAD, OPTIONS.

Paso 2: Escaneo de Puertos y Servicios

Comando: sudo nmap -sS -sV -O -Pn -T4 217.154.224.228 -p-

Se detectaron servicios y versiones en múltiples puertos, incluyendo HTTP (80), SSH (22), y DNS (53).

Paso 3: Escaneo de Vulnerabilidades

Comando: sudo nmap --script vuln -p 21,22,80,443,139,445,3306,8443 217.154.224.228

Se identificaron servicios potencialmente vulnerables. Se observó que el puerto 53 (DNS) ejecuta dnsmasq 2.78.

Paso 4: Análisis del Sitio Web

  • nikto -h http://217.154.224.228
  • gobuster dir -u http://217.154.224.228/ -w /usr/share/wordlists/dirb/common.txt

Resultado: no se detectaron rutas ocultas ni formularios dinámicos. Apache desplegado sin aplicaciones web adicionales.

Paso 5: Análisis del Servicio DNS

Se realizaron pruebas simuladas de ataque de spoofing y overflow sobre dnsmasq. Los ataques no tuvieron éxito, indicando protección activa o versión parcheada.

Pruebas con tcpdump confirmaron que el puerto 53 UDP está abierto.

Paso 6: Simulación de Ataques

  • sudo hping3 -2 -p 53 -c 10 -d 120 --baseport 1050 217.154.224.228
  • sudo tcpdump -i any port 53

Resultados: el servidor responde, pero no fue afectado, indicando robustez ante ataques de flood DNS básicos.

Conclusión

El servidor 217.154.224.228 mostró estar correctamente configurado, con servicios actualizados y sin vectores de ataque evidentes. Las pruebas de fuerza bruta, inyecciones y overflow no tuvieron efecto. El firewall permite tráfico DNS, pero el sistema mostró defensa contra manipulación maliciosa.
